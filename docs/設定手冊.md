# Local Typeless 設定手冊

本手冊說明：

1. **語音轉文字（STT）在哪台機器、用 CPU 還是 GPU 執行**
2. **如何更換背後的模型**（STT 模型與 LLM 模型）
3. **公司內部 gateway（`corp` profile）**的設定與第一次連線測試
4. **圖片插入、串流辨識與長口述整理設定**
5. **歷史紀錄儲存與自動清理管理（Storage）**

---

## 0. 先知道：設定檔在哪裡、什麼時候生效

| 檔案 | 用途 | 修改後何時生效 |
|---|---|---|
| `config/config.yaml` | **主要設定檔**：STT 執行方式、LLM 連線、熱鍵、輸出 | **重開 UI** |
| `config/config.example.yaml` | 範本（不要直接改；`config.yaml` 不存在時才會被讀取） | — |
| `config/glossary.yaml` | 術語詞庫 | **重開 UI** |
| `prompts/*.md` | 各模式的 LLM 指令（摘要 / 整理 / 投影片） | **下一次錄音**（不用重開） |

- 用文字編輯器打開，存檔時請用 **UTF-8**。
- YAML 以**空白縮排**表示層級（不要用 Tab），冒號後面要有一個空白。
- `config/config.yaml` 已排除在 git 之外，可以放你自己的連線設定。
- 改完後可先在專案資料夾執行下列指令檢查（會列出目前使用的 STT 設定、GPU 是否可用、LLM 是否連得上）：

  ```
  .venv\Scripts\python.exe -m local_typeless.cli check
  ```

- 面板底部狀態列也會顯示目前的 STT profile 與 LLM 連線狀態。

## 1. 語音轉文字（STT）在哪台機器執行

### 1.1 設計原則：STT 一律在「這台電腦」執行

語音轉文字使用 `faster-whisper`，**音訊永遠不會離開本機**（公司內部無法另開語音 API，因此 STT 必須 100% 本機）。
你能選的是「這台電腦的 **CPU** 還是 **GPU**」，以及用多大的模型。

### 1.2 三種預設執行方式（STT profile）

在 `config/config.yaml` 的 `stt_profiles` 底下已定義三組：

| Profile | 執行硬體 | 模型 | 特性 |
|---|---|---|---|
| `cpu_fast`（預設） | CPU | `small` | 最省資源、速度快；術語辨識稍弱 |
| `cpu_accurate` | CPU | `large-v3-turbo` | 較準確，CPU 上較慢 |
| `gpu_local` | NVIDIA GPU | `large-v3-turbo` | 準確又快，**需先安裝 GPU 函式庫（見 1.4）** |

### 1.3 如何切換

打開 `config/config.yaml`，修改最上方這一行，存檔後重開 UI：

```yaml
active_stt_profile: cpu_fast      # 改成 cpu_accurate 或 gpu_local
```

**臨時切換（不改設定檔）**：從命令列啟動時加參數，只影響這一次：

```
.venv\Scripts\python.exe -m local_typeless.ui --stt-profile gpu_local
.venv\Scripts\python.exe -m local_typeless.ui --device cpu          # 強制改用 CPU
```

> 桌面捷徑不帶參數，永遠依 `config.yaml` 的設定。

### 1.4 使用 GPU 的前置作業（目前尚未安裝）

目前這台電腦有 NVIDIA GPU（Quadro T1000），但缺少 CUDA 函式庫，所以 `gpu_local` 會**自動退回 CPU**（不會當機，狀態列/紀錄會標示 `cpu (fallback)`）。
要真正啟用 GPU，在專案資料夾執行一次（約下載 1.1 GB）：

```
uv pip install --python .venv\Scripts\python.exe nvidia-cublas-cu12 nvidia-cudnn-cu12
```

程式會自動找到這些函式庫。裝完用 `check` 確認看到 `CUDA usable: yes`，再把 `active_stt_profile` 改成 `gpu_local`。

### 1.5 自動降級保護

- `device: cuda` 時若 GPU 初始化或推論失敗（函式庫缺失、顯示記憶體不足等），會自動改用 `cpu` + `int8` 並記錄警告，**這段口述不會遺失**。
- 降級後在本次 UI 執行期間都會留在 CPU，重開 UI 才會再試 GPU。

### 1.6 可以把 STT 放到別台機器（例如 DGX）嗎？

目前**不支援，且是刻意的設計**（公司環境的合規要求：音訊不出本機）。
若未來在非公司環境確實需要，程式已預留介面：在 `src/local_typeless/stt/` 新增一個實作 `STTEngine`（`stt/base.py`）的類別，並在 `stt/__init__.py` 的 `create_stt_engine()` 依設定分派即可，其他模組不用改。

## 2. 如何更換背後的模型

系統有兩個模型：**STT 模型**（本機，把聲音變文字）與 **LLM 模型**（遠端，負責摘要/整理/投影片）。

### 2.1 更換 STT 模型

修改 `config/config.yaml` 中**目前使用的那組 profile**，例如：

```yaml
stt_profiles:
  cpu_fast:
    device: cpu              # cpu | cuda | auto
    model_size: small        # 見下表
    model_path: null         # 離線模型資料夾（見 2.2）；有填就優先使用
    compute_type: int8       # CPU 用 int8；GPU 用 int8_float16 或 float16
    cpu_threads: 6           # CPU 執行緒數
    beam_size: 2             # 越大越準但越慢（1–5）
    vad_filter: true         # 過濾停頓，避免思考空白時產生幻覺文字，建議保持 true
    language: null           # null = 自動偵測；固定中文可填 zh
```

可用的 `model_size`：

| 模型 | 大小 | 建議用途 |
|---|---|---|
| `small` | 小 | CPU 日常使用（預設） |
| `medium` | 中 | CPU 上折衷 |
| `large-v3-turbo` | 大（速度經最佳化） | GPU，或能接受較慢的 CPU |
| `large-v3` | 最大 | 最高準確度，需 GPU |

注意事項：
- **第一次使用某個模型會自動從網路下載**（數百 MB 到約 1.5 GB），之後使用快取。
- `device: cpu` 時 `compute_type` 請用 `int8`；用命令列 `--device cpu` 覆寫時程式會自動改成 `int8`。

### 2.2 離線模型（公司內網無法下載時）

在可上網的電腦先下載模型資料夾，再複製到公司電腦：

```
.venv\Scripts\hf.exe download Systran/faster-whisper-small --local-dir D:\models\faster-whisper-small
.venv\Scripts\hf.exe download mobiuslabsgmbh/faster-whisper-large-v3-turbo --local-dir D:\models\faster-whisper-large-v3-turbo
```

然後在 profile 中指定路徑（Windows 路徑請用單引號包起來）：

```yaml
    model_path: 'D:\models\faster-whisper-large-v3-turbo'
```

`model_path` 資料夾存在時優先使用；不存在則改用 `model_size` 下載。

### 2.3 更換 LLM 模型

LLM 設定在 `config/config.yaml` 的 `llm_profiles`，用哪一組由 `active_llm_profile` 決定：

```yaml
active_llm_profile: dev          # dev | corp | 你自己新增的名稱
```

範例設定檔內建兩組：

| Profile | 用途 | 需要你填的內容 |
|---|---|---|
| `dev`（預設） | 自架的 OpenAI 相容服務（vLLM / Ollama / SGLang） | `base_url`、`model` |
| `corp` | 公司內部 gateway（見第 3 節） | `base_url`、`model`、金鑰與下方的相容性欄位 |

**只換模型**：把該 profile 的 `model:` 改成伺服器上的模型名稱。可用的名稱可用 `check` 指令查看（`LLM reachable. Models: ...`）。

**新增一台伺服器或一組設定**：複製一整段 profile、改名，再把 `active_llm_profile` 指向它：

```yaml
llm_profiles:
  my_server:
    provider: openai_compatible        # vLLM / Ollama / SGLang 等 OpenAI 相容服務都用這個
    base_url: http://主機:埠/v1
    api_key_env: MY_SERVER_API_KEY     # 金鑰放在這個 Windows 環境變數（不要把金鑰寫在檔案裡）
    model: 模型名稱
    timeout_sec: 30.0                  # 超過就改輸出原文，不會遺失
    temperature: 0.2                   # 越低越穩定
    max_tokens: 2048
    extra_headers: {}                  # 需要額外 HTTP header 時填
    extra_body:                        # 會原樣併入請求內容
      chat_template_kwargs:
        enable_thinking: false         # Qwen3 思考模式；開啟會慢約 8 倍
```

**設定金鑰**（只需一次）：

```
setx MY_SERVER_API_KEY "你的金鑰"
```

設定後重開 UI 即可，不需要登出（程式會直接讀取 Windows 使用者環境變數）。伺服器不需要金鑰時可不設，程式會送 `Bearer EMPTY`。

### 2.4 LLM 連不上時會怎樣？

超時、斷線、金鑰錯誤時，系統會**改為輸出經術語校正後的原文**，面板顯示黃色提示，口述內容不會遺失。
狀態列會顯示原因：`金鑰錯誤或未設定`、`連線逾時`、`無法連線`、`伺服器錯誤 (HTTP n)`。

## 3. 公司內部 gateway（`corp` profile）

`corp` profile 用來連公司內部的 LLM gateway。**啟用時只改設定、不改程式**；常見的差異（憑證、金鑰放哪個標頭、代理伺服器、路徑）都有對應欄位。

### 3.1 設定（`config/config.yaml`）

```yaml
  corp:
    provider: gateway
    base_url: https://<gateway 主機>/v1     # ← 換成實際網址
    api_key_env: GATEWAY_API_KEY              # ← 存放金鑰的環境變數名稱（金鑰不寫進檔案）
    model: <模型名稱>                        # ← 換成公司可用的模型名稱
    timeout_sec: 15.0
    temperature: 0.2
    max_tokens: 2048
    extra_headers: {}                       # 公司要求的額外 header（例如部門代碼）
    extra_body: {}                          # 會原樣併入請求內容
    # 以下為相容性欄位，寫出來的都是預設值，只改需要的
    api_key_header: Authorization           # 金鑰放在哪個標頭，例如 api-key、X-API-Key
    api_key_prefix: "Bearer "               # 金鑰前面的字；填 "" 表示只送金鑰本身
    verify_tls: true                        # false = 不檢查憑證（只用來排查問題）
    ca_bundle: null                         # 公司根憑證 PEM 檔路徑；null = certifi + Windows 憑證存放區
    use_env_proxy: true                     # false = 不經代理伺服器，直接連線
    proxy: null                             # 指定這個 profile 專用的代理伺服器網址
    chat_path: /chat/completions            # 接在 base_url 後面的路徑
    models_path: /models                    # 健康檢查用；gateway 沒有模型清單時填 ""
```

| 欄位 | 什麼時候要改 |
|---|---|
| `ca_bundle` | `check` 顯示憑證不受信任。預設已信任 Windows 憑證存放區，公司電腦通常不用改；若仍失敗，向 IT 取得根憑證 PEM 檔並填路徑 |
| `api_key_header` / `api_key_prefix` | gateway 不用 `Authorization: Bearer <金鑰>`，例如要求 `api-key: <金鑰>` |
| `use_env_proxy` / `proxy` | 公司電腦設有對外代理伺服器，內部網址被送去代理而連不上。也可改設環境變數 `NO_PROXY` |
| `chat_path` / `models_path` | 路徑不是 `/chat/completions`、`/models` |
| `extra_body` | 需要額外參數，例如關閉 Qwen3 思考模式：`chat_template_kwargs: {enable_thinking: false}` |
| `timeout_sec` | 經常出現「連線逾時」而改輸出原文時調高 |

### 3.2 第一次連線測試

1. 向公司確認：API 網址、認證方式（哪個標頭）、可用模型名稱、速率限制。
2. 填好 `corp` 區塊，設定金鑰：`setx GATEWAY_API_KEY "金鑰"`。
3. 不必先切換預設 profile，直接指定 `corp` 測試：

   ```
   .venv\Scripts\python.exe -m local_typeless.cli --llm-profile corp check
   ```

   輸出會列出金鑰變數是否已設定（不會印出金鑰）、憑證來源、代理設定，接著做兩項測試：
   取得模型清單（`LLM reachable`），以及實際送一次極短的對話請求（`LLM chat test: OK`）。
   失敗時會多印一行 `hint:` 指出該改哪個欄位。
4. 用公開語料的測試音檔跑一次完整流程：

   ```
   .venv\Scripts\python.exe -m local_typeless.cli --llm-profile corp file <音檔.wav> --mode clean
   ```

5. 確認無誤後把 `active_llm_profile` 改成 `corp`，重開面板。模型不同，prompt 可能需要微調（`prompts/*.md`）。

| `check` 的訊息 | 處理方式 |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` | 設定 `ca_bundle` |
| `HTTP 401` / `HTTP 403` | 檢查金鑰變數、`api_key_header`、`api_key_prefix` |
| `HTTP 404` / `HTTP 405` | 檢查 `base_url`、`chat_path`、`models_path` |
| `HTTP 407` 或訊息含 proxy | 設定 `NO_PROXY`，或 `use_env_proxy: false` |
| `LLM connection failed` | 檢查網址、DNS、VPN、代理設定 |
| 模型清單失敗但 `LLM chat test: OK` | gateway 沒有模型清單，把 `models_path` 設為 `""` |

### 3.3 如果 gateway 不是 OpenAI 相容格式

只需修改 `src/local_typeless/llm/gateway_adapter.py` 中的兩個函式：

- `_transform_request(payload)`：把標準請求內容轉成 gateway 要的格式
- `_extract_response(data)`：從 gateway 的回應中取出文字

其他模組（錄音、STT、面板、斷線回退）都不用改。

## 4. 圖片插入、串流轉錄與長口述設定

系統支援在口述中插入截圖與圖片，並具備即時串流 STT、背景佇列處理與防截斷長文分段整理機制。

### 4.1 附件插入設定（表格、圖片、網址、文字片段與 `output.table_paste_format`）

在 `config/config.yaml` 中配置：

```yaml
images:
  enabled: true       # 是否啟用附件插入（預設 true）
  trigger: paste      # paste：按貼上鍵時插入（預設）；auto：剪貼簿一出現新圖就插入
  poll_ms: 150        # 僅 auto 模式使用：剪貼簿輪詢週期（毫秒）

hotkeys:
  paste_image: "<alt>+v"   # 錄音中把剪貼簿的內容（表格/圖片/網址/文字）插入到目前位置

output:
  paste_step_delay_ms: 300  # 多步交錯貼上時，每一步之間的停頓（毫秒）
  image_paste_mode: auto    # 圖片貼上方式：auto（預設，依目標軟體決定）、image 或 path
  path_paste_apps:          # auto 模式下把圖片貼成絕對路徑的程式清單（預設為各種終端機）
    - windowsterminal.exe
    - cmd.exe
    - powershell.exe
    - pwsh.exe
    # 其餘預設值見 config.example.yaml
  table_paste_format: auto  # 表格貼上格式：auto（預設，依目標軟體決定）、markdown 或 html
  table_html_apps:          # auto 模式下以 HTML 表格貼入的程式清單（不分大小寫）
    - winword.exe
    - powerpnt.exe
    - outlook.exe
    - olk.exe
    - excel.exe
    - onenote.exe
    - ms-teams.exe
    - teams.exe
```

- **操作方式（預設 `trigger: paste`）**：在錄音中按 `Alt + V` 或面板上的「貼上」按鈕，系統會依剪貼簿內容自動判定並插入對應標記：
  1. **表格**（`[表N]`）：剪貼簿含有單一 HTML 表格（`<table`，外圍多餘文字在 20 字以內且至少 2 格）或 TSV 純文字（至少 2 列 2 欄且欄數一致）。從 Excel 複製時即使同時帶有圖片格式，也會優先判定為表格。
  2. **圖片**（`[圖N]`）：剪貼簿含有圖片資料。
  3. **網址**（`[連結N]`）：剪貼簿為單一 `http://` 或 `https://` 網址。
  4. **文字片段**（`[文字N]`）：剪貼簿為其他非空純文字（超過 20,000 字元自動截斷並記錄 warning）。注意：在錄音中剪貼簿若是純文字，按貼上快捷鍵也會直接將該文字作為文字片段插入。
- **貼上輸出行為**：
  - **網址與文字片段**：在輸出貼上前直接代換回整理後的文字中，不產生額外的貼上步驟。若口述中僅包含網址或文字片段，仍維持一次貼上完成。
  - **表格**：貼成 Markdown 時併入文字一起貼上（表格前後各空一行，不增加貼上步驟）；貼成 HTML 表格時是獨立的一步。依 `output.table_paste_format` 設定：
    - `auto`（預設）：在貼上當下檢查前景視窗的程式名稱。若該程式在 `output.table_html_apps` 清單中（如 Office 的 Word、Excel、PowerPoint、Outlook、Teams），會提供 CF_HTML 讓它貼出真正的富文字表格；若是清單以外的軟體（如瀏覽器裡的 Claude.ai、ChatGPT 對話框、記事本、終端機），則自動貼成 Markdown 文字表格，避免瀏覽器對話框接收 HTML 時把表格壓平成無格式純文字。若想讓其他自訂編輯器接收 HTML 表格，只需在 `table_html_apps` 加入該軟體之 `.exe` 檔名（不分大小寫）。
    - `markdown`：一律貼入 Markdown 格式文字表格。
    - `html`：一律放入 CF_HTML 與 Markdown 雙格式。
    - 剪貼簿若寫入失敗，一律自動安全退回貼 Markdown 文字。
  - **圖片**：依 `output.image_paste_mode` 設定：
    - `auto`（預設）：前景視窗的程式在 `output.path_paste_apps` 清單中（預設為 Windows Terminal、cmd、PowerShell 等終端機）時，貼成圖檔的絕對路徑並併入文字一次貼完；其他程式則維持獨立步驟貼上圖片本身（文字 → 圖片 → 文字）。想讓 VS Code、Cursor 的內建終端機也貼路徑，可加入 `code.exe`、`cursor.exe`，但該程式的其他輸入框也會一併改成貼路徑。
    - `image`：一律貼圖片本身。
    - `path`：一律貼絕對路徑。
  - **檔案**（`[檔案N]`）：一律貼成檔案的絕對路徑並併入文字。路徑含空白時會加上雙引號，並與前後文字以空白隔開。
- **插入檔案的兩種方式**：
  1. 錄音中把檔案（可多選）從檔案總管拖到面板上。拖進來的圖檔也視為檔案，貼成原始路徑。
  2. 在檔案總管複製檔案後按 `Alt + V`。複製的若是圖檔，仍視為圖片（依上面的圖片規則處理）。
  - 檔案本身不會被複製、讀取或上傳，紀錄檔中只留下路徑。面板若以系統管理員身分執行，Windows 會擋下來自一般權限檔案總管的拖放。
- **本機隱私保護**：所有附件內容（圖片、表格 Markdown/HTML、網址、文字片段、檔案路徑）皆僅保存在本機 session 與紀錄中，遠端 LLM 僅會接收到 `[圖N]`、`[表N]`、`[連結N]`、`[文字N]`、`[檔案N]` 佔位標記，實體內容絕不外傳。
- **純文字目標限制**：若游標位於純文字環境（如記事本、終端機），圖片無法貼入，表格將呈現 Markdown 表格，文字與網址照常貼入。
- **何時調整 `paste_step_delay_ms`**：目標軟體反應較慢（遠端桌面、大型網頁表單）而出現順序顛倒或漏貼時，調高到 500 或 800。
- **為什麼預設不是 `Ctrl+V`**：`Ctrl+V` 會同時把內容貼進你正在使用的文件，結束後又貼一次。若仍想使用，可把 `paste_image` 改成 `"<ctrl>+v"`。

### 4.2 串流語音辨識與背景佇列（`streaming`）

```yaml
streaming:
  enabled: true       # 邊錄音邊在背景切段進行 STT 辨識（預設 true）
  min_chunk_sec: 12.0 # 錄音超過此長度後，遇到靜音即切段送出辨識（秒，預設 12.0）
  max_chunk_sec: 28.0 # 強制切段上限，於最近 3 秒內最安靜處切斷（秒，預設 28.0）
  silence_sec: 0.5    # 判定為停頓的連續靜音時長（秒，預設 0.5）
```

- **即時逐字稿**：錄音期間，後台 STT 執行緒會隨說話停頓持續切段辨識，懸浮面板會即時顯示累計之逐字稿內容。
- **背景佇列與連續錄音**：按下停止鍵後立即回到就緒狀態（IDLE），無需等待後台處理完畢即可立刻按下快捷鍵進行下一段口述。
- **焦點保護機制**：若在新一段錄音進行時，先前口述完成後台整理，該結果會保留於佇列中，待當前錄音結束後依序自動貼上，絕不搶奪游標焦點或打斷當前口述。
- **何時調整**：若電腦資源較為受限，或希望回到舊版「停止錄音後才阻塞執行 STT」的單執行緒流程，可將 `streaming.enabled` 設為 `false`。

### 4.3 長口述分段整理（`refine`）

```yaml
refine:
  block_target_chars: 700  # Clean 模式每區塊目標字數（預設 700）
  block_max_chars: 1000    # Clean 模式每區塊最大字數上限（預設 1000）
  context_chars: 150       # 帶給下一區塊作為前文語境參考的結尾字數（預設 150）
```

- **分段整理（Block-wise Refinement）**：在 Clean 模式下，長篇口述會於標點符號處無損切分為約 700 字（上限 1000 字）之區塊逐一整理。第二區塊起會自動帶入前一區塊尾端文字作為理解語境（Prompt 明令禁止重複輸出前文）。
- **部分回退提示**：若某個區塊因模型超時或格式異常失敗，系統僅將該區塊以原始逐字稿（經術語校正）呈現，其餘區塊依然正常整理輸出。懸浮面板會明確顯示黃色提示：`部分段落 LLM 失敗（X/Y），該段顯示原文`。
- **防截斷保護**：若 LLM 回應因達到長度上限而被截斷（`finish_reason == "length"`），系統會偵測並視為錯誤自動回退，確保絕不輸出被切斷之殘缺文字。
- **何時調整**：若使用的 LLM 產生速度慢或對於長段落較易超時，可調小 `block_target_chars`（例如改為 400～500）。

### 4.4 歷史紀錄與儲存位置（`storage`）

每次口述完成後，結果會存成一個 Markdown 檔；錄音中插入的圖片也存在這裡設定的位置。

```yaml
storage:
  records_dir: records           # 文字紀錄；相對路徑以專案資料夾為準，也可填絕對路徑如 D:/Dictation/records
  images_dir: records/images     # 插入的圖片
  retention_days: 90             # 保留天數；0 表示永久保留
  filename_format: "{date}-{time}_{mode}_{title}"   # 檔名（不含 .md）
```

- **檔名變數**：`{date}` 為 `YYYYMMDD`；`{time}` 為 `HHMMSS`；`{mode}` 為 `整理`、`摘要`、`投影片` 或 `轉換`；`{title}` 為結果開頭的前 20 個字（會去掉檔名不允許的字元，空白時為「無標題」）。只能使用這四個變數。
- **資料夾結構**：紀錄依月份放在 `records/2026-11/20261112-143005_整理_今天先講 ILT 的基本概念.md`；圖片放在 `records/images/<日期-時間-代碼>/img_1.png`。
- **檔案內容**：開頭是時間、模式、是否回退、圖片數；接著是「結果」（圖片以 Markdown 連結呈現）與「原文」。
- **自動清理**：每次存檔時刪除超過 `retention_days` 的紀錄與圖片，並移除清空的月份資料夾。只會刪除本工具建立的檔案（月份資料夾內的 `.md` 與圖片擷取資料夾），所以把位置指到既有的資料夾也不會動到你自己的檔案。

### 4.5 所有會累積的檔案放在哪裡（`cache_dir` 與 `storage`）

本工具寫到磁碟的檔案預設全部放在專案資料夾的 `records\` 底下，可以各自改到別的位置：

| 內容 | 設定 | 預設位置 | 會不會一直變大 |
|---|---|---|---|
| 口述紀錄（Markdown） | `storage.records_dir` | `records\<年-月>\` | 超過 `retention_days`（預設 90 天）自動刪除 |
| 插入的圖片 | `storage.images_dir` | `records\images\` | 同上 |
| 最近一次錄音 `last_recording.wav` | `cache_dir` | `records\cache\` | 只保留一份，每次錄音覆寫 |
| 面板歷史 `history.jsonl` | `cache_dir` | `records\cache\` | 只保留最近 `history_max` 筆（預設 20） |
| 執行紀錄 `ui.log`、`ui_fault.log` | `cache_dir` | `records\cache\` | `ui.log` 會自動輪替，大小有上限 |
| 錄音中的暫存音訊 | `cache_dir` | `records\cache\chunks\` | 辨識完就刪；異常殘留的檔案超過一天會在啟動時清掉 |
| 教學模式的樣本 | `cache_dir` | `records\cache\teach\` | 你自己新增的資料，不會自動刪除 |

想把全部搬到別的磁碟，改這三個設定即可（絕對路徑或相對於專案資料夾的路徑都可以）：

```yaml
cache_dir: D:/Dictation/cache

storage:
  records_dir: D:/Dictation/records
  images_dir: D:/Dictation/images
```

改完重新啟動面板。舊位置的檔案不會自動搬移，需要的話請自行複製過去。

語音模型不在此列：它由 Hugging Face 存放在 `%USERPROFILE%\.cache\huggingface\hub\`，大小固定，不會隨使用增加；
要改位置請設定環境變數 `HF_HOME`，或用 `model_path` 指向自己的模型資料夾（見 2.2）。

| 現象 | 原因與處理 |

## 7. 口述紀錄 Review 與個人詞典擴充

### 7.1 功能說明

系統提供「檢查口述紀錄」功能，主動分析儲存的歷史口述紀錄檔（`storage.records_dir`），以無 LLM 的純規則比對找出潛在的新詞與辨識疑慮：
1. **辨識疑慮（`[?]`）**：整理結果中緊鄰 `[?]` 標記的詞彙。
2. **拼寫變體（Variant）**：尚未列入詞庫的英文詞彙或片語，但在歷史紀錄中出現大小寫、空格、連字號不一致或編輯距離相似的寫法（例如 `curvilinear` 與 `curve linear`）。
3. **整理替換詞（Corrected）**：LLM 在整理時將語音辨識原文替換掉的詞彙（跨紀錄累計出現達 2 次以上）。

### 7.2 資料隱私與安全性（資料會送到哪裡）

- 掃描候選詞完全在**本機**以規則演算法完成，不消耗任何網路流量。
- 只有當找到候選詞時，系統會呼叫**一次**你設定的內部 LLM（即 `config.yaml` 內 `active_llm_profile` 指定的端點）。
- 送往 LLM 的內容**僅限候選詞及其前後約 30 字的上下文**，請 LLM 協助給出最可能的標準寫法、簡短定義與專有名詞判斷。完整口述文章、圖片、音訊**絕不會送出**。
- 若 LLM 無法連線或逾時，系統會自動退回純規則模式顯示，不影響檢查流程。

### 7.3 操作流程與如何還原

1. 在側邊面板底部狀態列（或訊息區）按滑鼠右鍵，點擊「檢查口述紀錄…」。
2. 點擊「開始檢查」：系統預設只會掃描上次檢查後新增或修改的紀錄（由 `cache_dir/review/state.json` 記錄）；勾選「重新檢查全部紀錄」可強制全量重新掃描。
3. 針對列出的問題檢視上下文，確認標準寫法、自行輸入正確詞彙、標記「這不是專有名詞」（記入忽略清單不再詢問），或「略過」（略過的項目在日後勾選「重新檢查全部紀錄」時會再次出現）。
4. 點擊「套用設定到詞庫」，系統會將標準術語與聽錯別名安全寫入個人詞庫 overlay（`config/glossary.user.yaml`）。
5. **如何還原**：每次套用前系統會自動保留備份檔（`.user.yaml.bak`）。若套用後欲撤銷，點擊視窗內的「復原上一次套用」，系統會立即還原回套用前的詞庫狀態。

## 8. 草稿視窗（`draft`）

```yaml
draft:
  enabled: true     # 草稿視窗流程：邊講邊整理，文字進到可編輯的草稿
  autosave: true    # 未完成的草稿保存在 <cache_dir>/draft.json，重開程式後還原
```

- `enabled: true`（預設）時，錄音不再自動貼到原本的視窗；每一小段辨識完就送 LLM 去贅字，結果插在草稿的游標位置。需要 `streaming.enabled: true`，否則自動退回舊流程。
- 每段多長由 `streaming.min_chunk_sec`／`max_chunk_sec` 決定（預設 12／28 秒）。調小會更即時，但每段太短時辨識和整理的品質會下降。
- LLM 連不上時，該段改放「詞庫正規化後的原文」，視窗下方會顯示有幾段未整理；不會丟字。
- 嵌入的檔案路徑、圖檔路徑和貼上的文字只存在本機。按「重新整理全文」時，它們會先換成 `[文字N]` 標記再送出，回來後換回原文；標記若被 LLM 弄丟，這次結果不採用。整理結果顯示在視窗下半，草稿不會被覆蓋。
- 貼上的圖片存在 `storage.images_dir` 底下，檔名為 `draft-日期-時間-序號.png`，不會被自動清理刪除。
- 「完成」時存的紀錄檔格式與一般紀錄相同，位置在 `storage.records_dir`。
- `enabled: false`：回到「講完整段整理、自動貼上」的流程，`[圖N]`、`[表N]` 等附件標記與 4.1 的設定只在這個流程使用。
